# Figma workflow

1. Discover the actual authorized Figma tools. A read-only MCP integration cannot execute drawing scripts. Never obtain or store tokens in this repo.
2. Before creating a new file, load the installed `figma-create-new-file` guidance. Before every `use_figma` call load `figma-use`. For visible compositions also load `figma-generate-design`; for reusable components/variables load `figma-generate-library`. Follow their current requirements and include their names in `skillNames`. If read as MCP resources, use the `resource:` prefixes. Use `create_session` when provided and pass its session ID unchanged.
3. Inspect file/page metadata and discover existing libraries/components/variables. Use `search_design_system` when available. Reuse the user's existing design system in production work. Never publish a library or set Ready for dev merely because a design was drawn.
4. Record the user's request, exact scope, target file and known node IDs in the dashboard workspace. Choose a new file or clearly identified new page for the starter script. Existing-node edits require a receipt and before-values; do not overwrite unrelated nodes.
5. `fdv figma` outputs a standalone MCP body. It creates a new page, variable collection, font variable, panel component and instances, then eight state frames. The new page is intentional; run once. Native editable bars/lines/text are calculated from the spec, not traced from an image. The function can run with the standard Plugin API too, but a plugin lifecycle wrapper is not provided.
6. Save the return object as receipt.json; retain file key externally if the integration does not provide it. On an uncertain error, inspect the canvas before retrying; do not delete a partially built page automatically. On a definite pre-execution error, fix the cause and retry once.
7. Generate measure.js from receipt.json and run it read-only. Save measurements.json; run `fdv audit`. Measurement checks report unresolved/mixed/gradient paints as unmeasured. They do not guess contrast across images or composited backgrounds.
8. Inspect a screenshot at relevant viewing sizes, including mobile where required. Fix only demonstrated issues and recheck once. Record a screen-reader/keyboard test as pending until implemented and actually tested.
9. Save the request, receipt, checks, screenshot evidence and user decision in the workspace. Handoff includes formulas, data dictionaries, filter semantics, state behavior, tokens, components, node links, rule exceptions and untested runtime work.

For existing library components, the agent composes with those components instead of running the self-contained starter renderer. Do not pretend the starter automatically imports a design system. Other chart types can be authored with the agent using the same rules, with explicit numerical validation before drawing.
